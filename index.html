Placing twenty products with a genetic algorithm

I assigned twenty products to eight warehouse zones under the constraints from the brief. Fitness is a penalty total; lower is better. The written report, and a seeded re-run of the same operators, both come back at 82. Several rules pull the same product toward different zones, so 82 is the cheapest leftover penalty I found, not a perfect plan.

Overview

The brief is Assignment 2: Warehouse Storage Optimization Using Genetic Algorithm. Twenty named products go into eight zones, each with a weight cap, under nine penalty rules. I submitted a single Python 3 file (standard library only), a short report, and viva notes. Tournament selection of size 5, two-point crossover, per-gene mutation at 0.08, and elitism of two chromosomes run for up to 900 generations on a population of 150.

The report’s best fitness is 82. The original file has no random.seed. The companion script src/warehouse_ga.py uses the same operators and, with --seed 0 (the default), reaches 82 at generation 45 and keeps it through generation 900. That is the plan described below.

The data

Twenty products and eight zones, taken from the brief and hard-coded in both scripts. There is no external dataset. The fitness function follows the brief’s “affected products” lists, which is not always the same as the column flags: Ice Cream is High in the Demand column but is not charged for sitting outside Z6; Wheat Sacks at 40 kg are not “heavy”, because heavy means over 40 kg.

How the algorithm is built

A chromosome is a list of twenty integers, one zone per product, P1 to P20. The population of 150 starts random. Each generation: sort by penalty, copy the two best unchanged, and fill the rest with tournament selection (size 5), two-point crossover, and per-gene mutation at 0.08. The loop stops at 900 generations, or at a fitness of 0. In every run I have done, it uses the full 900.

The original file’s function defaults are population 100, 200 generations, mutation 0.1 and tournament size 3. The actual call at the bottom of that file — and the companion default — is 150, 900, 0.08 and tournament 5.

A product in Z8 that is not on the whitelist+12 per product

Zero is out of reach for structural reasons, not because the search gave up early. The six fragile items weigh 87 kg and Z3 holds 80; the five hazardous items weigh 107 kg and Z5 holds 80; eight high-demand items weigh 213 kg and Z6 holds 60 kg, and five of those eight also have a cold-shelf or floor-storage rule. The viva notes say the same thing: the algorithm minimises the total, and some leftover penalty is expected.

The first generation’s best was 247, with a mean of 384.2. The curve drops quickly — 91 by generation 31, 87 by 43 — and lands on 82 at generation 45. After that the best does not move. The population mean at the end is still around 124; mutation keeps stirring the rest, and elitism holds on to 82.

Twenty violations remain: five high-demand misses, Motor Oil out of Z5, Hand Sanitizer out of Z3, and thirteen category splits. They are listed in results/violations.csv. I would not call this the unique optimum — it is a strong plan that the report found, that seed 0 finds, and that several other seeds find as well.

Twelve seeded runs

Seven of twelve seeds finished at 82, five at 88. The mean was 84.5, the median 82. None in that set came in under 82. The table is in results/seeded_runs.csv.

Training and result files

The algorithm does not train on a held-out set; every generation is scored with the same penalty function. The files worth opening:

  • data/products.csv — the twenty products, with the named sets the fitness function uses.
  • data/zones.csv — the eight zones and their capacities.
  • results/fitness_history.csv — best, mean, median and worst fitness for all 900 generations.
  • results/best_plan.csv and results/product_assignments.csv — the seed-0 plan.
  • results/violations.csv and results/penalty_breakdown.csv — how 82 is made up.
  • src/warehouse_ga.py and src/i222327_A02_A.py — the companion script and the original file.
  • docs/assignment/A2-…pdf, the report, and the viva notes.

How to run

Python 3, with the packages in requirements.txt if you want the plots. The CSV tables in data/ are already written.

Linux / macOS

git clone https://github.com/rohaan2802/Genetic_Algorithm.git
cd Genetic_Algorithm
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 src/warehouse_ga.py

Windows

python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python src\warehouse_ga.py

That runs the default: population 150, 900 generations, mutation 0.08, seed 0, and writes files under results/. Optional flags: --seed, --no-seed, --data-dir, --results-dir, --no-plots, --quiet. The original unseeded file is src/i222327_A02_A.py.
